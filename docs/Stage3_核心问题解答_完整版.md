# Stage 3 质检方案：核心问题解答与建议

## 📋 三个核心问题的答案

### 问题 1：论文中 UniMatch+DOVER 的输入是原视频还是渲染后的视频？

#### ✅ 答案：原始视频（打标前）

**证据 1：代码实现**
```python
# stage3_gpu.py 第 119-132 行
# 直接从 tar 读取原始 mp4
mp4_bytes = tf.extractfile(f"{sample_id}.mp4").read()

# 解码原始视频
frames_rgb = _decode_frames(mp4_bytes)

# 直接传给 UniMatch 和 DOVER
flow_val = unimatch_flow_magnitude(frames_rgb, flow_fn)
dover_val = dover_score(frames_rgb, dover_fn)
```

**证据 2：论文逻辑**
- **UniMatch 评估**：相机运动幅度、场景运动 → 与渲染无关
- **DOVER 评估**：压缩伪影、模糊、曝光 → 评估原始视频质量
- **Table 6 阈值**：针对原始视频的固有特征设计

**证据 3：质检目标**
- 目的：筛选**高质量原始视频**用于训练
- 如果用渲染视频：评估的是渲染质量，不是数据源质量
- 如果用原始视频：评估数据源本身，更合理

#### 结论
UniMatch 和 DOVER 的输入是**原始视频**（`.mp4` 文件），不是渲染后的视频。

### 问题 2：是否应该在打标前进行数据筛选？

#### ✅ 答案：是的，应该在打标前筛选

**理由 1：效率考虑**

当前流程（推测）：
```
原始视频 → Stage 1-2（相机标注）→ Stage 3（质检）→ 训练
            ↑ 耗时最大              ↑ 过滤 30-50%
```

优化流程（推荐）：
```
原始视频 → Stage 3（质检）→ Stage 1-2（相机标注）→ 训练
            ↑ 过滤 30-50%      ↑ 只处理高质量视频
```

**节省**：
- Stage 1-2 的相机标注（COLMAP）是最耗时的
- 不需要标注低质量视频（节省 30-50% 计算）

**理由 2：质量保证**
- 早期过滤：模糊、静态、压缩严重的视频
- 确保标注工作聚焦在高质量样本
- 提高最终数据集的整体质量

**理由 3：论文设计意图**

Table 6 的阈值针对原始视频特征：
```yaml
unimatch_flow:    [3, 100]    # 原始视频的运动
dover:            [0.35, 1.0]  # 原始视频的质量  
color_saturation: [30, 180]    # 原始视频的色彩
```

这些指标**不依赖相机标注**，可以在标注前评估。

#### 推荐方案：两阶段质检

```
阶段 1：早期质检（粗筛）
原始视频 → UniMatch + DOVER（基础阈值）
    ↓ 过滤明显低质量（30-40%）
候选视频

阶段 2：相机标注
候选视频 → COLMAP 标注
    ↓
标注数据

阶段 3：精细质检（细筛）
标注数据 → 相机质量 + VLM + 场景切换
    ↓ 过滤标注失败（10-20%）
最终训练集
```

**优势**：
- 早期过滤大部分低质量视频
- 后期精细检查标注质量
- 平衡效率和质量

## 🔧 技术细节

### UniMatch + DOVER 的独立性

**不依赖相机标注的原因**：

1. **UniMatch 评估运动**：
   - 光流 = 像素位移
   - 来自原始视频帧
   - 与相机内外参无关

2. **DOVER 评估质量**：
   - 压缩伪影、模糊、噪声
   - 来自视频编码和拍摄
   - 与 3D 重建无关

3. **色彩饱和度**：
   - HSV 色彩空间
   - 来自原始 RGB
   - 与相机标注无关

**依赖相机标注的指标**（Stage 3-B）：
- 相机轨迹平滑度
- 重投影误差
- 焦距稳定性
- 场景一致性
