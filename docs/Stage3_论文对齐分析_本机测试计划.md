# Stage 3 质检方案：论文对齐分析与本机测试

## 📋 核心问题分析

### 问题 1：论文中 UniMatch+DOVER 的输入是什么？

#### 关键发现：**原始视频 vs 渲染视频**

**结论**：根据代码和论文逻辑，**UniMatch 和 DOVER 应该使用原始视频**。

**证据**：

1. **代码实现证据**（`stage3_gpu.py`）：
```python
def process_sample_stage3(...):
    # 直接从 tar 中读取原始 mp4 文件
    mp4_bytes = tar.extractfile(f"{sample_id}.mp4").read()
    
    # 解码原始视频
    frames_rgb = _decode_frames(mp4_bytes)
    
    # 直接传给 UniMatch 和 DOVER
    flow_val = unimatch_flow_magnitude(frames_rgb, flow_fn)
    dover_val = dover_score(frames_rgb, dover_fn)
```

2. **论文逻辑推理**：

**质检目标**：筛选高质量的**原始视频**用于训练
- 如果用渲染后的视频：
  - ❌ 评估的是渲染质量，而不是原始数据质量
  - ❌ 渲染错误会掩盖原始视频的问题
  - ❌ 需要先完成相机标注，增加了流程复杂度

- 如果用原始视频：
  - ✅ 评估的是**数据源本身**的质量
  - ✅ 可以在标注前就过滤低质量数据
  - ✅ 节省计算资源（不需要标注低质量视频）

3. **具体评估内容**：

**UniMatch（光流）评估**：
- 相机运动幅度（步行 vs 静止）
- 场景运动复杂度
- **与渲染无关**：光流是原始视频固有特性

**DOVER（质量）评估**：
- 压缩伪影（原始视频编码质量）
- 模糊和噪声（原始拍摄质量）
- 曝光和色彩（原始视频美学）
- **与渲染无关**：评估的是视频本身的感知质量

### 问题 2：是否应该在打标前进行数据筛选？

#### 结论：**是的，应该在打标前筛选**

**理由**：

1. **流程效率**：
```
当前流程（推测）：
原始视频 → Stage 1-2（相机标注，慢）→ Stage 3（质检）→ 训练

优化流程（推荐）：
原始视频 → Stage 3（质检，快）→ Stage 1-2（相机标注）→ 训练
              ↓
          过滤 30-50% 低质量视频
```

**节省**：
- 不需要标注低质量视频（节省大量计算）
- Stage 1-2 的相机标注是最耗时的步骤

2. **数据质量保证**：
- 早期过滤低质量数据（模糊、静态、压缩严重）
- 确保后续标注工作聚焦在高质量样本上

3. **论文 Table 6 的设计意图**：
```yaml
# Table 6 的阈值针对的是原始视频特征
unimatch_flow:    [3, 100]    # 原始视频的运动
dover:            [0.35, 1.0]  # 原始视频的质量
color_saturation: [30, 180]    # 原始视频的色彩
```

## 🔍 与论文对齐的关键点

### 1. 数据流向

**论文逻辑**（推测）：
```
原始视频采集
    ↓
Stage 3：视觉质检（UniMatch + DOVER）
    ↓ 过滤
高质量视频
    ↓
Stage 1-2：相机标注（COLMAP 等）
    ↓
标注数据
    ↓
训练数据集
```

**当前实现**：
```
原始视频采集
    ↓
Stage 1-2：相机标注
    ↓
Stage 3：视觉质检
    ↓
训练数据集
```

**差异**：当前实现在标注后才质检，可能浪费了标注资源。

---

### 2. Table 6 阈值的含义

**论文设计意图**：

| 指标 | 阈值示例 | 筛选目的 |
|------|---------|---------|
| `unimatch_flow: [3, 100]` | 光流 3-100 像素/帧 | 过滤静态场景（boring）和过度运动 |
| `dover: [0.35, 1.0]` | 质量 0.35-1.0 | 过滤模糊、噪声、压缩伪影严重的视频 |
| `color_saturation: [30, 180]` | 饱和度 30-180 | 过滤过暗或过曝的视频 |
| `scene_cuts_max: 1` | 最多 1 次切换 | 确保视频连续性 |

**这些阈值针对的是原始视频的固有特征**，不依赖于相机标注。

---

### 3. 质检时机的影响

**如果在标注前质检（推荐）**：
```
优势：
✅ 节省标注成本（不标注低质量视频）
✅ 提高数据集整体质量
✅ 加快数据处理流程

劣势：
⚠️ 可能过滤掉一些标注后仍可用的视频
   （但论文阈值设计应该已考虑这点）
```

**如果在标注后质检（当前）**：
```
优势：
✅ 可以结合相机标注质量综合判断
✅ 更灵活（可以保留一些边界样本）

劣势：
❌ 浪费了低质量视频的标注成本
❌ 流程更长
❌ Stage 1-2 需要处理所有原始视频
```

## 💡 建议的流程调整

### 方案 A：两阶段质检（推荐）

```
1. 早期质检（Stage 3 前置）：
   原始视频 → UniMatch + DOVER（基础阈值）
       ↓ 过滤明显低质量（30-40%）
   候选视频

2. 相机标注（Stage 1-2）：
   候选视频 → COLMAP 标注
       ↓
   标注数据

3. 精细质检（Stage 3 当前位置）：
   标注数据 → 相机质量检查 + VLM
       ↓ 过滤标注失败（10-20%）
   最终训练集
```

**优势**：
- 早期过滤掉大部分低质量视频
- 后期精细检查标注质量
- 平衡效率和质量

---

### 方案 B：保持当前流程（如果标注已完成）

如果 Stage 1-2 已经处理了大量数据：
```
当前流程：
原始视频 → Stage 1-2（标注）→ Stage 3（质检）→ 训练

优化点：
1. 优化 Stage 3 性能（已在进行）
2. 添加增量质检（新数据先过 Stage 3）
3. 记录质检统计，指导后续数据采集
```
