## 前言：为什么要学这些？

在视频生成、3D重建、AR/VR等应用中，我们需要理解**视频是如何被拍摄的**，才能正确地处理和生成它们。

### 核心问题

1. **视频归一化**: 为什么要统一分辨率和帧率？
2. **相机模型**: 3D世界如何投影到2D图像？
3. **坐标变换**: 如何描述相机在空间中的位置和朝向？

这些概念是理解 `normalize.py` 和整个 SANA watermark pipeline 的基础。

## 第一部分：视频归一化

### 1.1 什么是视频归一化？

**通俗理解**: 就像标准化试卷一样，把各种不同来源的视频（手机拍的、相机录的、网上下载的）统一成一个标准格式，方便后续处理。

在 `normalize.py` 中，标准格式是：
- **分辨率**: 1280x720 (720p)
- **帧率**: 16fps
- **编码**: H.264, CRF=18（高质量）

### 1.2 为什么需要归一化？

#### 实际场景举例

假设你有三个视频：
- 📱 手机视频: 1080x1920 (竖屏), 30fps
- 📹 相机视频: 3840x2160 (4K), 60fps  
- 💻 网络视频: 640x360 (低清), 24fps

如果不统一：
- ❌ 神经网络需要处理各种输入尺寸（效率低）
- ❌ 批处理（batch processing）无法进行
- ❌ 对比实验结果不公平（分辨率不同）

统一后：
- ✅ 所有视频都是 1280x720 @ 16fps
- ✅ 可以批量训练/推理
- ✅ 实验结果可对比

### 1.3 归一化的两个步骤

#### 步骤1: 缩放 (Scale)

**目标**: 调整分辨率，但要保持画面比例

```python
scale = max(target_w / original_w, target_h / original_h)
```

**关键参数**: `force_original_aspect_ratio=increase`

这个参数的意思是：**宁可放大过头，也不留黑边**

##### 例子1: 下采样（缩小）

```
原始: 1920x1080 → 目标: 1280x720

scale_x = 1280/1920 = 0.667
scale_y = 720/1080 = 0.667
scale = max(0.667, 0.667) = 0.667

缩放后: 1280x720 ✅ 刚好合适！
```

##### 例子2: 上采样（放大）

```
原始: 640x480 → 目标: 1280x720

scale_x = 1280/640 = 2.0
scale_y = 720/480 = 1.5  
scale = max(2.0, 1.5) = 2.0  （选更大的！）

缩放后: 1280x960 ⚠️ 超出了目标高度
```

#### 步骤2: 裁剪 (Crop)

当缩放后尺寸超出目标时，需要裁剪掉多余部分。

**Center Crop**: 从中心裁剪，保留画面核心内容

```python
crop_x = (scaled_w - target_w) // 2
crop_y = (scaled_h - target_h) // 2
```

继续例子2：
```
缩放后: 1280x960
目标: 1280x720

crop_x = (1280 - 1280) // 2 = 0  （宽度不需要裁）
crop_y = (960 - 720) // 2 = 120  （上下各裁120像素）

最终: 从 (0, 120) 位置开始，取 1280x720 的区域
```

## 第二部分：相机模型基础

### 2.1 针孔相机模型

这是计算机视觉最基础的模型，把真实相机简化为一个小孔。

#### 物理原理（通俗版）

想象你用一个纸箱做针孔相机：

1. 🕳️ 纸箱前面戳一个小孔（针孔）
2. 🌳 外面的树（3D物体）
3. 📄 光线穿过小孔，投影到后面的纸上（2D图像）

**关键**: 3D世界 → 2D图像 的转换过程

### 2.2 相机内参矩阵 K

**作用**: 描述相机本身的光学特性（和相机在哪儿无关）

```
K = [fx  0  cx]
    [ 0 fy  cy]
    [ 0  0   1]
```

#### 参数含义（白话文）

| 参数 | 物理意义 | 生活类比 |
|------|---------|---------|
| `fx, fy` | 焦距（像素单位） | 望远镜的放大倍数 |
| `cx, cy` | 主点/光心坐标 | 镜头中心对准的位置 |

#### fx 和 fy 的影响

**fx/fy 越大 → 放大效果越强**

```
fx = 400  → 广角镜头（能看到更多景物）
fx = 800  → 标准镜头  
fx = 1200 → 长焦镜头（物体被拉近）
```

##### 实际例子

假设你在5米外拍一个人：

- 📷 `fx=400` (广角): 能拍到人和周围的树、房子
- 📷 `fx=800` (标准): 能拍到人的全身
- 📷 `fx=1200` (长焦): 只能拍到人的上半身（放大了！）

**重要**: fx/fy 改变了，投影到图像的位置就变了！

### 2.3 投影公式

从3D点 `(X, Y, Z)` 到2D像素 `(u, v)` 的转换：

```
┌   ┐   ┌        ┐ ┌   ┐
│ u │   │fx  0 cx│ │ X │
│ v │ = │ 0 fy cy│ │ Y │
│ 1 │   │ 0  0  1│ │ Z │
└   ┘   └        ┘ └   ┘

然后做"透视除法":
u_pixel = u / Z
v_pixel = v / Z
```

#### 为什么要除以 Z？

**透视效应**: 越远的物体，投影越小

- 🚗 同样大小的车，5米外看起来很大
- 🚗 同样大小的车，50米外看起来很小

这就是 `1/Z` 的效果！

### 2.4 主点 (cx, cy) 的影响

**主点**: 光轴（相机正对的方向）穿过图像平面的那个点

正常情况下：
```
cx = image_width / 2  = 640  (对于1280x720)
cy = image_height / 2 = 360
```

**如果主点偏移了会怎样？**

- 主点偏右 (cx > 640): 图像左边能看到更多内容
- 主点偏上 (cy < 360): 图像下边能看到更多内容

这就是为什么 **center crop 会影响 cx, cy**！

## 第三部分：坐标系与变换

### 3.1 三个坐标系

在视频处理中，我们需要处理三个坐标系：

#### 1️⃣ 世界坐标系 (World)

- **定义**: 固定的参考系，比如房间的一个角
- **用途**: 描述场景中所有物体的"绝对位置"
- **类比**: 地图上的经纬度

#### 2️⃣ 相机坐标系 (Camera)

- **定义**: 以相机为中心的坐标系
- **约定**: 
  - Z轴：指向相机前方（拍摄方向）
  - X轴：指向相机右侧
  - Y轴：指向相机下方（或上方，看约定）
- **用途**: 计算投影更方便
- **类比**: 你眼睛看到的"前后左右"

#### 3️⃣ 图像坐标系 (Image)

- **定义**: 像素坐标 `(u, v)`
- **原点**: 通常在图像左上角
- **单位**: 像素
- **类比**: 照片上的像素位置

### 3.2 坐标变换流程

```
3D世界点 (X_world, Y_world, Z_world)
    ↓ [外参变换: R, t]
相机坐标 (X_cam, Y_cam, Z_cam)
    ↓ [内参投影: K]
图像坐标 (u, v)
```

### 3.3 外参矩阵：c2w vs w2c

**外参**: 描述相机在世界中的位置和朝向

#### w2c (World-to-Camera)

**含义**: 把世界坐标转换到相机坐标

```
P_camera = R_w2c · P_world + t_w2c
```

或者用齐次坐标：
```
┌         ┐   ┌         ┐ ┌         ┐
│ P_camera│   │R_w2c  t │ │ P_world │
│    1    │ = │  0    1 │ │    1    │
└         ┘   └         ┘ └         ┘
```

**用途**: 计算投影（配合内参K使用）

#### c2w (Camera-to-World)

**含义**: 把相机坐标转换到世界坐标

```
c2w = [R_c2w | t_c2w]
      [  0   |   1  ]

其中: c2w = w2c^(-1)  （互为逆矩阵）
```

**用途**: 
- 描述相机位置（t_c2w 就是相机在世界中的位置）
- 用于运动估计、SLAM

#### 通俗理解

- **w2c**: "我（相机）眼中的世界"
- **c2w**: "世界眼中的我（相机在哪儿）"

### 3.4 齐次坐标

**为什么要用齐次坐标？**

普通坐标 `(X, Y, Z)` 无法用矩阵乘法表示平移：
```
❌ 不能写成: [X']   [R] [X]
             [Y'] = [R] [Y]  （缺少平移项！）
             [Z']   [R] [Z]
```

齐次坐标 `(X, Y, Z, 1)` 可以：
```
✅ 可以写成: [X']   [R | t] [X]
             [Y'] = [0 | 1] [Y]
             [Z']           [Z]
             [1 ]           [1]
```

**关键**: 多加一维，让平移也能用矩阵表示！

### 3.5 旋转矩阵 R

**性质**: 
- 3×3 正交矩阵
- `R · R^T = I` (单位矩阵)
- `det(R) = 1` (行列式为1)

**物理意义**: 描述相机的朝向

#### 例子：绕Z轴旋转θ角

```
R_z(θ) = [cos(θ)  -sin(θ)  0]
         [sin(θ)   cos(θ)  0]
         [  0        0     1]
```

如果 θ=90°（逆时针转90度）：
```
R_z(90°) = [0  -1  0]
           [1   0  0]
           [0   0  1]

原本指向X的方向 → 现在指向Y
原本指向Y的方向 → 现在指向-X
```

## 第四部分：实战问题

### 4.1 问题：center crop 如何影响相机内参？

这是 `normalize.py` 中的核心问题！

#### 场景描述

```
原始视频: 1920x1080, fx=1000, cx=960, cy=540
目标视频: 1280x720

经过 scale + crop 后，内参会改变！
```

#### 数学推导

##### 第1步：缩放

```
scale = max(1280/1920, 720/1080) = 0.667

fx_new = fx_old × scale = 1000 × 0.667 = 667
fy_new = fy_old × scale = 1000 × 0.667 = 667
cx_new = cx_old × scale = 960 × 0.667 = 640
cy_new = cy_old × scale = 540 × 0.667 = 360
```

##### 第2步：裁剪（如果需要）

假设缩放后是 1280x960（高度超了）：

```
crop_y = (960 - 720) // 2 = 120

新主点:
cx_final = cx_new - crop_x = 640 - 0 = 640
cy_final = cy_new - crop_y = 360 - 120 = 240  ⚠️ 变了！
```

#### 结论

**缩放影响**: fx, fy, cx, cy 都按比例缩放  
**裁剪影响**: cx, cy 会偏移（取决于裁剪位置）

### 4.2 对下游任务的影响

#### 如果下游需要准确的相机参数：

1. **3D重建**: 内参不准 → 深度估计错误
2. **多视角合成**: 内参不准 → 视角融合错位
3. **AR应用**: 内参不准 → 虚拟物体放置位置错误

#### 解决方案

**方案1**: 在 normalize 前先做相机标定，然后调整内参

```python
# 伪代码
K_original = calibrate_camera(original_video)
K_normalized = adjust_intrinsics(K_original, scale, crop_offset)
save_intrinsics(K_normalized)
```

**方案2**: 跳过归一化，直接用原始视频（如 `test_stage2_ablation.py`）

```python
# Stage2 直接处理原视频
art = run_default(original_video_path, work_dir)
# 返回的 art.intrinsics 是基于原始分辨率的
```

**方案3**: 记录变换参数，下游任务逆向调整

```python
transform_record = {
    'scale': 0.667,
    'crop_offset': (0, 120),
    'original_size': (1920, 1080),
    'target_size': (1280, 720),
}
```

## ❓ 常见问题 FAQ

### Q1: 为什么要用齐次坐标？
**A**: 为了用矩阵乘法统一表示平移和旋转。普通坐标下，旋转是矩阵乘法，平移是加法，不统一。

### Q2: c2w 和 w2c 哪个更常用？
**A**: 看应用场景。计算投影用 w2c，描述相机轨迹用 c2w。它们互为逆矩阵。

### Q3: 主点一定在图像中心吗？
**A**: 理论上不一定！镜头组装误差、光轴偏移都会导致主点偏离。但实践中通常假设在中心。

### Q4: fx 和 fy 为什么可能不相等？
**A**: 像素可能不是正方形！早期CCD传感器的像素是矩形，现在基本都是正方形了。

### Q5: 为什么单目视觉有尺度模糊性？
**A**: 因为缺少深度信息。场景放大2倍+相机后退2倍 = 相同的图像投影。需要额外约束（已知物体尺寸、IMU数据等）。

### Q6: normalize 会损失信息吗？
**A**: 
- 下采样：会损失高频细节（但CRF=18保留了很多）
- 上采样：不会增加信息，只是插值
- 裁剪：会丢失边缘视野

### Q7: 能否跳过 Stage1 直接处理原视频？
**A**: 可以！`test_stage2_ablation.py` 就是验证这个。但归一化可以提高batch效率和实验可重复性。

## 📝 总结

### 核心要点

1. **视频归一化** = Scale + Crop
   - 统一格式方便处理
   - 但会改变相机内参！

2. **相机内参** K = [fx, fy, cx, cy]
   - 描述相机光学特性
   - 不随相机移动而变化

3. **相机外参** = R + t (或 c2w)
   - 描述相机空间位置和朝向
   - 每帧都可能不同（相机运动）

4. **坐标变换**
   ```
   世界坐标 →[外参]→ 相机坐标 →[内参]→ 图像坐标
   ```

5. **实战注意**
   - Center crop 会偏移主点
   - 下游任务需要调整后的内参
   - 可视化是理解的最佳工具
